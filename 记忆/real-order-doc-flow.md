2026-07-28 用户提供了真实单据照片（广东尝元绿色食品有限公司，豆制品配送），实际流程是：

1. **客户发来《特殊采购表》**（客户方系统打印，抬头写"（广东尝元绿色食品有限公司）特殊采购表"）
   列：商品编码 / 菜品 / 订菜总数 / 规格 / 总数量 / 采购价。
   关键：「订菜总数」是**按点位拆开的**，例如干张 = (020#西餐厅)6斤 +(089)3斤 +(131#2)1斤 +(216#2)2斤 +(280)8斤 …，需要汇总。
2. **对上我方的产品价格库**（就是《报价单》那张：商品名称/规格/销售价，按大类分组：干货豆制品、冷冻品、水货豆制品、其它品类、粉面制品；带二维码和订货电话）。
3. **生成《销售单》给客户**：单据编号、客户名、销售日期/送货日期、序号/商品名称/单位/数量/单价/金额/客户点位/备注、数量合计、金额合计、大写金额、订货电话、制单人、送货人签名、收货人签名。

已核对的样单（客户：涯食乐餐饮管理服务有限公司，2026-07-27）：21 行，金额合计 1614.70，逐行单价×数量全部对得上；数量合计 466.2 是把板/斤/盒**混着相加**的（他们系统就这么做）。

四个从单据里看出来的真实难点：
- **名称对不上**：客户的菜品名 ≠ 我方商品名。小板豆腐→尝元小板(28规格)、小胶板豆腐→小板豆腐5-6斤、北方老豆腐→老豆腐(斤)、炸豆腐→九龙炸豆腐、烟香干→尝元薄烟干、卤香干→卤豆干、凉皮→卷卷凉皮。这才是真正要解决的匹配问题。
- **同一商品拆多行**：不同点位价格不同就拆行，把点位号写进备注。样单里干张 62斤@3.80 和 1斤@3.40（备注 131）、尝元小豆泡 13.7斤@5.50 和 4斤@5.10（备注 131）。即**价格是按点位/客户走的**。
- **单位与规格**：单位有 板/斤/盒/包/串/块，规格里带换算（中板豆腐 7斤/板、老豆腐 15斤/板），有的按板下单有的按斤下单。
- **缺价**：样单里「益群山水豆腐(400g) 2盒」单价金额是空的，等于送了没计钱。

**Why:** 这推翻了之前"粘贴微信订单文字→AI识别"的设想——真实输入是一张结构化表格，不是聊天记录。
**How to apply:** 做工具时按"读采购表 → 名称映射 → 按点位汇总/拆行 → 取价 → 出销售单"来设计，不要按聊天解析来设计。相关：[[food-delivery-quote-system]]、[[guanmai-incumbent-system]]
