老板 2026-08-04 定的省钱铁律，每次都要遵守：

- **输出**：任何表格/整理结果一律写进 .xlsx 或 .csv，绝不在对话里打印整张表。回复只给三样：文件路径、行×列数、异常项（哪几格有问题）。禁止复述表格内容、禁止回显他贴进来的原文、禁止客套小结。
- **认表**：先用 markitdown 看结构，只读表名+表头定位；要哪列就用 openpyxl/pandas 精确读那几列/那几格。绝不为了回答「用第几列」把整张 sheet 读进上下文。
- **读图**：照片/PDF 用代码 OCR/解析，结果直接写 .xlsx，只回「已写入 N 行 × M 列 → 路径」。
- **回头核对**：用代码比对两份数据，只输出对不上的那几格（位置 + 两边的值），不重贴任何一份原文。
- **缓存纪律**：一次会话里不中途换模型、不改被缓存的文件——两者都让上下文重算。认表这类活开 Sonnet 会话；读图/核对这类零容错的活开 Opus 会话，分开开别混切。
- **批量历史单**：不在交互里一条条跑，生成走 Batch API 的脚本（进出各五折、24h 异步），**他确认后再执行**。

**Why:** 1000 张单/天，识别成本 ¥1.35 万/月（见 [[ai-recognition-cost-plan]]）；对话里回显表格是纯浪费，一次几千 token。缓存纪律那条技术上成立：缓存按模型隔离，换模型 = 整段前缀重算。

**How to apply:** 写脚本 → 出文件 → 报路径和异常，就这三步。零容错的活（读图、核对）不许为省钱降模型，那条由 [[zero-silent-errors-rule]] 管。
