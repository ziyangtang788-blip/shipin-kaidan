客户（广东尝元绿色食品有限公司，观麦账号 T2011436 / qdcysp）在用**观麦 Guanmai** 生鲜配送 SaaS（`station.guanmai.cn`）。

**2026-07-28 定了：做 (B) 补位，不做替代。** 观麦继续当主系统（订单/进销存/财务都在里面），我们只解决它最痛的一环。

痛点确认：客户微信发来《特殊采购表》的**图片**，尝元的人要**一条条手工敲进观麦**，量大、极易出错。这就是要解决的那一段。

观麦已经做对的部分（我们要接住、不要重造）：
- **商品 / 商品管理 / 报价单管理**：一个客户 = 一张报价单，目前 **183 张**（东方市场、华丰超市大沥店、佳丰顺德超市、康瑞达食材配送中心、涯食乐…），每张显示"在售商品数"（5 到 86 不等）。
- 点进一张报价单是商品明细表：商品名(C 编码) / **规格名(D 编码)** / 分类 / 销售单价 / 定价公式 / 销售规格 / 销售价 / 参考成本 / 上架状态。
- **客户专属叫法就存在「规格名」里**：同一个商品 C1854171「尝元大板豆腐（14-15斤）」下挂着两个规格名「客家豆腐（大板）」和「九龙豆腐（大板）」；C1854284「尝元炸豆干」的规格名是「油豆干」。
- 报价单明细页右上角有**导出**按钮 → 名称对照表和分客户价可以直接导出来用，不用手工重建。

**How to apply:** 设计工具时，价格库和名称对照**从观麦导出**，别让用户再录一遍。输出要么直接出销售单、要么出能导回观麦的文件——这一步是省人力的关键。相关：[[real-order-doc-flow]]、[[food-delivery-quote-system]]
