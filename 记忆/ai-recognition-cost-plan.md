2026-08-04 算的账。49 份真实单实测：进 175,339 / 出 87,608 token。

**单张 ¥0.45**（Opus 5，$5/$25，那一版还没挂缓存）。

8/4 又跑了 10 份，缓存生效后：$0.48 / ¥3.5 → **单张 ¥0.35**，1000 单/天 = **¥350/天 ≈ ¥1.05 万/月**。
**输出占 86%**（$0.417/$0.483），输入连零头都算不上——省钱只有一条路：让模型少吐字。
按 79 品 / 209 段估，真正的 JSON 大约 8 千 token，实际吐了 16,677——**约一半是思考 token**。

⚠ 批量跑-日志.txt 里那句「49 份 ≈ $9.20」是按 $15/$75（已弃用的 Opus 4.1 价）算的，真实是 $3.07。别再拿那个数吓自己。

杠杆按性价比排序（都还没做）：
1. **effort 没设，思考默认开着**——Opus 5 省略 thinking 参数 = 自适应思考开启，思考 token 按 $25 计。加 `output_config:{effort:"low"}` 估计省 ¥130/天。别用 `thinking:{disabled}`，Opus 5 关思考会把 `<thinking>` 标签漏进正文，打乱剥JSON。
2. **格子表键名瘦身**——中文长键 + 空字段照写；聚农商贸单 166 段光分布就三四千 token。估计省 ¥90-130/天。
3. ~~缓存零命中~~ **已经在命中了，这条划掉**。8/4 跑 10 份实测：命中 24,610 token，省了 $0.11（约 19%）。之前说的「零命中」是拿旧日志看的，那版脚本还没挂 cache_control。剩下的：配送开单台.html 里「核对提示够不到 1024 门槛」还是过期注释，Opus 5 门槛已降到 512，核对那一路还能再挂。
4. **读法按客户记一次**——原以为是最大的一条，**实测下来只值 10%**：137 份真单里 116 png + 5 jpg + 3 pdf = **90% 是照片**，只有 13 个 xlsx。照片每次都得重新 OCR，没有「记一次」的余地。这条别再当救命稻草。
5. **分模型**收益最小（Opus→Sonnet 只省 40%），放最后，且只动认表和核对，图片识别保 Opus——见 [[zero-silent-errors-rule]]。

全做完估计 ¥0.45 → ¥0.12~0.18/单。

**⛔ 2026-08-04 老板拍板：整条省钱线暂停。** 先把系统做对、上线跑顺，再回头谈成本。
**硬前提：准确率 100/100，任何省钱手段不许影响判断。** 谁也不许拿"应该差不多"上线——
必须拿 `基线-49份-opus-结果.json` 当标尺实测，⛔ 条数和读出来的数字一个都不许变，才准动。

effort 那条的技术底（查过官方文档，2026-08-04）：
- effort 砍的是**思考深度**，砍不动 JSON 正文长度——Opus 5 上 effort 不是控制正文长短的杠杆，
  正文要短只能改提示词。所以省的只是那一半思考 token。
- Opus 5 **严格遵守 effort 等级**，低档会把工作范围收缩到"刚好够用"——读图认数字这种零容错的活，
  这正是风险点。官方说法也是：low/medium 在 Opus 5 上表现远超档位，**但必须先跑自己的评测确认质量不掉**。
- `thinking:{disabled}` 除了漏 `<thinking>` 标签，还有更凶的第二个坑：偶尔把**工具调用写成普通文字**，
  那一轮看起来成功、实际啥都没执行、不报错。且 disabled 配 `xhigh`/`max` 直接 400。
- 缓存门槛 512 已确认（Opus 5 从 1024 降下来）。

下一步（解冻之后才做）：按 [[token-cost-discipline]] 的规矩写 Batch API 测量脚本，同一批单跑 effort 三档比 ⛔ 条数和 token，等他确认再执行。
