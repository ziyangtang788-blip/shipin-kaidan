**2026-07-31 定的做法**：客户要能在工具里按客户改自己的报价单（改价、加品类、改叫法、停售），不用回观麦。做成两层：

- **底层** = 观麦导入的价格库（`数据-价格库.js`），只读，重新导入整份覆盖
- **覆盖层** = 工具里改的，单独存，**重新导入观麦数据不会冲掉它**
- 每条价标明来源「观麦 / 你改过」，能一键还原成观麦的价

**2026-07-31 已实现**（本机版，在 [配送开单台.html](配送开单台.html) 的「客户 · 改价」标签页）：
- 客户卡片列表（177 家，可搜、可筛「改过的 / 有缺价的」）→ 点进去改
- 可改：单价、客户叫法、停售/恢复；可新增品类；单条还原、整家还原
- 数据全挂在原有的 `OV` 里（新增 `px` / `padd` / `plog` / `who`），所以「导出备份」一个文件全带走，将来搬云端只搬这一个包
- 关键接法：boot 顺序必须是 `ovLoad() → applyAdd() → applyPX() → buildIndex()`。反过来索引里还是观麦老价，改了不生效。`applyPX` 先用 `it._o` 快照复原再盖一遍，所以「还原」也能立刻生效
- 已实测：雅食乐攸县香干 2.60 → 9.99，回开单台 85 斤合计从 ￥221.00 变 ￥849.15

⚠ 同一客户会有**多条同名商品**（雅食乐有 2 条攸县香干，2.80 和 2.60）。改价时要看单位/规格分辨，只改一条不一定影响识别结果。

**改价必须留痕**：旧价 → 新价、改的人、时间。用户明确要「知道谁改的、什么时候」。已做：顶栏「操作人」按钮，没设置时第一次改价会弹窗问，不填不让改。

进销存那边的同类机制是 `DB.prodX` / `DB.custX`（加商品、安全库存、上下架、客户账期），跟这套是两份，将来上云要合并。

⚠️ **由留痕推出一条新需求**：要记「谁改的」就得有人的身份，而现在整个系统**没有任何用户概念**（单机网页，谁打开都一样）。所以云端版必须带上最简单的登录或至少「选操作人」。这条跟 [[cloud-shared-data-decided]] 一起做。

**现状有多难用**（说明为什么必须改）：改一个价要走五步 —— 观麦后台改 → F12 贴爬取脚本 → 下 CSV 到「下载」→ 右键跑 `工具-生成价格库.ps1` → 整份 `数据-价格库.js` 重新生成。要懂技术，操作员干不了。

**待工厂回答的问题**（悬着，不问清楚别定死）：
1. **对账、开票到底走观麦还是走我们？** 决定价格以谁为准。用户说不确定，要问工厂。在问清楚之前**按覆盖层做**（两边都兼容的那种），别做成替代观麦。
2. **他们自己有没有域名？** 用户以为已经给过我域名，其实给的是 `station.guanmai.cn` —— 那是观麦后台，是数据来源，不是能放我们工具的地方。要上线得另外注册。
3. 几台电脑、几个人同时用？谁有权改价？

**改名字要拆成两件事**：改「商品名」只影响销售单上印什么；改「客户叫法（规格名）」会牵动名称对照表，改了不同步下次就识别不出来。
